# Evidence — opcert-field CBOR decode-leniency divergence (Amaru vs cardano-node)

Supporting evidence for `dwarf/docs/finding-opcert-field-decode-leniency.md` (opcert family #6,
decoder-level differential). Feeding the SAME opcert-field-mutated Praos block-header CBOR to both
implementations' header decoders, **Amaru accepts three inputs cardano-node rejects at decode**:
`hot-vkey-truncated`, `cold-sig-truncated`, `opcert-extra-field`. Deterministic; reproduced across
preprod + mainnet base headers.

## Files

- `differential-report.json` — the full cross-decoder report (`opcert_field_decoder_diff`): per
  mutation, each decoder's outcome + the agree/divergence classification. 11 mutations, 8 agree, 3
  divergences, 0 crashes.
- `corpus/<mutation>.cbor` — the 11 mutated header vectors fed to both decoders (generated by the
  forger `mutate-opcert` from the base header; each rewrites only the opcert sub-structure).
- base header: `dwarf/corpora/opcert/field-mutations/base-header-mainnet-10817298.cbor` (a real
  mainnet Praos header both decoders accept unmutated).

## Decoders (both callable on the box)

- cardano-node 11.1.2: `dwarf-opcert-adversary-latest decode-praos-header`
  (`decodeFullAnnotator` of `Praos.Header StandardCrypto`).
- Amaru 10.11.20260918: `amaru-cbor-decode-block-header`
  (`from_cbor_no_leftovers::<BlockHeader>`), manifest
  `dwarf/targets/manifests/amaru-cbor-decode-block-header.yaml`; built binary on the box at
  `.../targets/amaru/target/release/amaru-cbor-decode-block-header`.

## Result

| divergent mutation | Amaru | cardano-node |
|---|---|---|
| hot-vkey-truncated (32 B → 16 B) | accept | reject: "Expected 32 number of bytes, but got 16" |
| cold-sig-truncated (64 B → 32 B) | accept | reject: "PinnedSizedBytes 64: wrong length, expected 64 bytes but got 32" |
| opcert-extra-field (append 5th elem) | accept | reject: "Size mismatch when decoding Record CBORGroup. Expected 5, but found 4." |

The other 8 mutations (counter negative/bignum/text/bytes, KES period text/negative, opcert
missing/duplicate field) are rejected by BOTH decoders (agreement). Decode-stage leniency only;
whether Amaru rejects these at later validation is a recommended follow-up (see the finding note).
