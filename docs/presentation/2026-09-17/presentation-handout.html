DWARF

A real-node adversarial test framework that turns deterministic workloads, faults, observations, and assertions into retained, reviewable evidence.

Execution boundary

Real implementations, real protocols, evidence-first verdicts

DWARF runs actual Cardano-node and Amaru software in controlled topologies. A scenario coordinates setup, load, fault, observation, recovery, and assertion phases; every useful claim must prove target identity, workload reachability, non-vacuity, and outcome.

Representative evidence

What the retained results actually say

Amaru rewards panic

Deterministic epoch-transition failure, reproduced 2,249 times in the official W34 control and matched to an upstream fix.

Fee boundary

At the exact minimum fee, Cardano-node accepted while Amaru rejected. A valid fault-free differential; breadth and closure remain limited.

Chain selection

466 mixed-network iterations across five regimes produced zero genuine selection divergences; nine flags were one-slot propagation jitter.

N2N state machine

Both targets reached all 24 protocol/class cells in Antithesis with no victim panic; protected-control naming invalidated the containment/recovery verdict.

Claim discipline

A failed run can find a bug. A passed run can prove very little.

DWARF classifies the claim, not merely the process exit: proven, partial, finding, harness-invalid, infrastructure-invalid, known/duplicate, or untested.

The framework is valuable when it preserves enough evidence to distinguish a node defect from a harness, topology, setup, or platform failure.
Proposed operating program

Measure useful real-node work without turning DWARF into a simulator

Reuse the existing execution and evidence machinery. Add wire transcripts, existing node telemetry, a small set of bounded instrumented builds, independent outcome observation, and resource cost per unit of useful work.

Proposed baseline gate

Repeatable before “fast”

  • 20,000 successfully processed blocks minimum
  • Three clean repetitions on the same host class
  • Zero new correctness divergence, panic, fatal exit, or permanent stall
  • All required cells and targets reached
  • Independent observer confirms outcome
  • Backlogs drain after fault removal

Initial relative review thresholds: goodput −10%, p95 latency +15%, recovery +20%, CPU/RSS per useful work +15%. These require stakeholder agreement and later calibration.

Cadence

Start small and make it routine

  • Amaru: weekly pinned candidate
  • Cardano-node: release candidate / release initially
  • Both: affected bundles after consensus, ledger, network, VM, or security changes
  • Harness changes: preflight plus known-good control before any new node claim

Scenario tags connect ownership and intent: correctness, consensus, ledger, network, recovery, performance, VM, security, adversarial, differential, and mixed-net.

What this still will not claim

Explicit boundaries

No production-network TPS, uncontrolled cross-hardware benchmark, full internal causation without tracing, comparable performance across different roles, finality beyond the observation horizon, or absence of instrumentation bias without a paired stock run.
