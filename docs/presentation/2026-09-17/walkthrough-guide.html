Fresh checkout → running DWARF

Use this opening to distinguish what DWARF ships from what the operator supplies. Do not expose credentials or machine-private configuration.

01 · Install

Get the packaged product

Clone the repository and use the documented Docker deployment path. DWARF provides the dashboard, controller, catalogs, schemas, adapters, and evidence layout.

02 · Configure

Supply the environment

Choose persistent storage, node images or binaries, topology inputs, and optional integration credentials. These are deployment authority, not public defaults.

03 · Start

Bring up the service

Start the packaged services and verify /healthz. The default deployment exposes the dashboard on :8787.

04 · Open

Enter through Learn

Open /learn on the deployed dashboard, then follow the same select, execute, inspect, and export path the product documents.

Narration boundary: the inspected deployment proves its pinned revision. A fresh-install walkthrough explains the supported path; it is not a new clean-room installation performed during the meeting.

Risk work packages/learn/risk-packages

Operate · complete current route tour

The current route tour follows OPERATE_SUB_NAV; registered detail routes are shown with their catalog owners.

Run and evidence loop7 routes

Overview/operate

Say: This is the operator home for current activity, retained runs, bundles, catalog inventory, and tool status. Counts describe inventory and framework outcomes, not bug totals.

Runs/operate/runs

Say: Search and filter retained executions here. A framework pass or failure still needs assertion and evidence inspection before classification.

Run detail/operate/runs/<id>

Say: This is the immutable inspection surface for manifest, exact scenario, events, logs, probes, assertions, metrics, and outputs. This is where a claim becomes independently inspectable.

Live run/operate/runs/<id>/live

Say: This streams an in-progress run and its log tail. Activity is useful, but completion and non-vacuous evidence remain separate gates.

Bundles/operate/bundles

Say: Bundles make a run portable for verification, import, and export. The archive preserves evidence without requiring trust in the presenter's terminal.

Timeline/operate/timeline

Say: Timeline correlates events retained across bundles. It cannot show an event the workload or node never emitted.

Audit/operate/audit

Say: Audit supports retrospective classification of retained runs. Classification improves the record; it cannot retroactively make a vacuous workload valid.

Definitions and comparison5 routes

Scenarios/operate/scenarios

Say: Scenarios are executable evidence contracts with runtime, seed, phases, primitives, and assertions. Search the exact demo ID here.

Profiles/operate/profiles

Say: Profiles hold reusable topology and environment choices. Keeping them separate lets one test intent run against pinned configurations.

Targets/operate/targets

Say: Target manifests pin implementation, input boundary, revision, and expected outcomes. Catalog presence does not prove runtime availability.

Compare/operate/compare

Say: Compare runs the same scenario against implementations and shows outcome differences. Current retained comparison evidence is useful but narrow.

Comparison detail/operate/compare/runs?run_a=&run_b=

Say: This dynamic view compares two exact retained run IDs. Meaningful interpretation requires equivalent inputs and compatible evidence.

Reusable asset catalogs8 catalogs

Primitives/operate/primitives

Say: Browse the full registry with schemas, executor provenance, compatibility, references, and deterministic source export. Registration is not execution evidence.

Profile templates/operate/profile-templates

Say: Inspect or export immutable topology scaffolds, then clone one into an editable profile.

Testcases/operate/testcases

Say: Inspect retained testcase provenance and operate on triage, replay, minimization, comparison, and promotion state without rewriting the source artifact.

Testcase buckets/operate/testcase-buckets

Say: Buckets are read-only derived groupings over testcase state; there is no separate bucket file to edit.

Corpora/operate/corpora

Say: Inspect, hash, preview, and export exact inputs. Token-gated curation is limited to the runtime overlay.

Generation grammars/operate/grammars

Say: Inspect structure/token pairs, clone a shipped pair, and save only a jointly validated runtime copy.

Risk work packages/operate/risk-packages

Say: Inspect planning status and resolve only evidence paths that actually exist; unresolved historical references remain explicit.

Plugins/operate/plugins

Say: Inventory and export read manifests and declared files without executing entrypoints. Approved runtime loading is not sandboxed.

Health, integrations, and control8 routes

Status/operate/status

Say: This exposes framework, storage, substrate, profile, and Moog readiness before execution. Idle external topology state is not automatically a failure.

Coverage/operate/coverage

Say: This aggregates coverage artifacts retained in bundles. It reports emitted evidence, not universal threat coverage.

Crashes/operate/crashes

Say: This groups candidate crashes by signature for triage. An empty view does not prove that no node can crash.

Schedule/operate/schedule

Say: This creates and controls recurring scenario entries. The surface exists, but an empty scheduler must not be described as an active test program.

Static analysis/operate/static-analysis

Say: This displays retained clippy, audit, and deny artifacts. It complements runtime testing and does not replace current upstream CI.

Config/operate/config

Say: This resolves runtime, storage, and integration configuration with secrets masked. Do not screen-share private values or edit during the presentation.

Notifications/operate/notifications

Say: This defines event rules and delivery configuration. A configured rule is not evidence that a webhook, email, or chat delivery was freshly proven.

Antithesis/operate/antithesis

Say: This guides build, validation, preflight, Moog submission, and polling. Submission or “running” state does not prove that the intended security workload executed.

Authoring without mutating the live catalog

Show the structured builders, raw JSON/YAML escape hatch, server-side validation, and exact write boundary. Opening, editing, and validating a draft are non-destructive; Save/Create is the explicit mutation.

Scenario template preview/operate/scenarios/new

Select a bundled template, enter a disposable lowercase name, and click Refresh preview. Show the rendered YAML and stop before Create scenario; existing files are not overwritten by this create path.

Say: A new scenario starts from a known schema and remains inspectable before it enters the catalog.

Scenario editor/operate/scenarios/<id>/edit

The shared builder validates structured or raw YAML/JSON before enabling save and keeps the catalog id immutable. Only a rehearsed disposable copy may be written.

Say: Validation blocks malformed structure; it does not prove runtime semantics.

Profile creation/operate/profiles/new

Clone a current profile template, edit the complete schema-backed definition in structured or raw mode, and stop before Create during the walkthrough.

Say: Profiles reuse topology and environment choices without copying test intent.

Target registration/operate/targets/new

The shared builder validates a complete target manifest with implementation, input boundary, exact upstream revision, invariants, and optional harness metadata. The binary must still exist before the target can run.

Say: A target manifest identifies a boundary; it is not proof that the binary is present or exercised.

Primitive scaffold/operate/primitives/new

Choose setup, load, probe, assertion, fault, or teardown and name the primitive. Submission generates starter executor, schema, test, and registry files that still require implementation and rebuild.

Say: Extensions join the versioned primitive contract rather than bypassing it.

Do not submit: Create scenario, save scenario, create profile, register target, or scaffold primitive during the main walkthrough. Preview is safe; the other actions write state.
