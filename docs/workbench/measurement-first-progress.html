01 · Original guidance

What the client asked for

The source request combines functional conformance, node-level performance distributions, stress tests, repeatable examples, threat/risk classification, and recurring execution.

Functional conformance

  • Ledger-rule scenario scoreboards
  • CBOR decode and self-consistency
  • Plutus result and CPU/MEM budget agreement
  • Header validation
  • Chain selection
  • Epoch stake-distribution comparison

Critical node measures

  • Simple transfer
  • Block application
  • Virtual machine
  • Epoch transition
  • Time to restart
  • Sync speed

02 · Measurement model

How DWARF approached it

A measurement is an observer, not another scenario engine. The scenario keeps the security intent; compatible taps add node-level evidence without converting DWARF into a simulator or generic benchmark framework.

01

Scenario

Real workload, adversarial input, fault and security assertion.

02

Profile

Reusable stock or patched measurement selection.

03

Identity gate

Exact implementation, release, source, image and patch identity.

04

Real-node taps

Stock traces, external probes, resources and minimal patched boundaries.

05

Evidence

Outcomes, distributions, raw/normalized records, report and portable bundle.

06 · Completion path

Highest-value next work

Finish the client-visible program in layers without leaving DWARF's security-testing purpose.

1 · repair

Automatic defaults

Make compatible passive profiles attach when a scenario omits measurement fields, while preserving explicit none.

2 · populate

Missing critical workloads

Add standardized transfer, restart, header-lifecycle and deep-chain-switch scenarios for both implementations.

3 · conform

Functional scoreboards

Aggregate ledger, CBOR, Plutus, header, chain-selection and SNAP results using pinned datasets and test identities.

4 · explain

Five client examples

Document why each exists, conditions, workflow, expected result, run method, functional requirement and one NFR.

5 · automate later

Recurring execution

Wire GitHub Actions/nightly/weekly only after workloads and baselines are stable enough to compare.

6 · last

Mixed comparison

Begin only after the same controlled program is authoritative independently for both implementations.

Claim boundary: DWARF now has a working, evidence-backed measurement engine for explicit Amaru and Cardano-node runs. It does not yet have the complete client conformance/regression program, stable release thresholds, or a mixed-node measurement result.
