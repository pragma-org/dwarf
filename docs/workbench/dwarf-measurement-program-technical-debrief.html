03 / tap architecture

Measurement sources stay separate from the test verdict.

Stock

Signals that the unmodified node already exposes: logs, network state, ledger events, and process state.

External

Observer-side evidence: workload accounting, process and cgroup resources, health, chain tips, restart gates, and sync endpoints.

Patched

Revision-locked internal timing taps. They retain integer elapsed_nanos, keep elapsed_micros, and report fractional microseconds.

Reserved

A declared source class for future instrumentation. It makes absence explicit; it is not fabricated evidence.

Flow: exact target → raw source records → normalized collectors → window correlation → report and raw evidence → dashboard → signed export/import. Assertions read evidence but measurement thresholds do not gate by default.

Precision rule: collectors prefer nanoseconds when present. For example, 2184 ns becomes 2.184 µs. Legacy whole-microsecond records still load. Card 03 stays on whole-microseconds-v1.

Child-friendly explanationSome measuring marks are already on the machine, some sit outside it, and some were added inside an exact copy. All marks send notes to the same evidence box.

05 / findings and resolutions

Findings stay visible when later evidence resolves the test path.

CBOR / preserved finding

Frozen Amaru b159172f… failed the 64-byte bound in the exact corpus. DWARF classifies the completed run as a node conformance finding and keeps the failed assertion. The exact upstream fixed revision d3a6dafc… passes the same corpus.

Plutus / active-chain resolution

The first Amaru topology did not prove an active Plutus V2 cost model. The additive topology uses a Cardano producer and Amaru consumer, pins genesis and parameters, activates the model on chain, and retains real transaction evidence.

Forks / semantic correction

The old strict raw-event monotonic rule was incorrect because legitimate same-height switches can occur. The new model preserves raw history and evaluates bounded canonical progress, convergence, correlations, and health separately.

What resolution does not mean

A later pass does not rewrite an earlier failure. A topology repair does not prove every Plutus workload. A converged fork test does not prove freedom from all deep-chain behavior.

Child-friendly explanationIf a test found a crack, we kept the picture of the crack. Then we tested the exact repaired brick. We did not erase the first picture.
06 / exact viewing steps

Open, inspect, export, and verify evidence in DWARF.

  1. Connect to the internal host and forward the dashboard: ssh -L 8787:127.0.0.1:8787 cardano-box.
  2. Open http://127.0.0.1:8787/learn/measurements. Read the revision and claim-boundary guidance first.
  3. Open a run link in a card dossier. Check the run ID, target identity, scenario, seed, collector states, assertions, and report.
  4. Use the raw-evidence links to inspect source records, window markers, exact target proof, and card-specific proof outputs.
  5. Export the evidence bundle from the run page. Verify it with dwarf/cardano-profile verify RUN_ID. Import into an isolated run directory and compare the manifest SHA-256.
  6. Use the workbench records for program-level context: runbook, status, exact goal, handoff, and completion proof.

10 / next work

Expand only after a new decision and a new frozen contract.

  • Choose whether to authorize a mixed-node comparison. If authorized, freeze common boundaries and do not reuse independent-run numbers as a benchmark.
  • Define stable thresholds only after enough qualified distributions exist across hardware and revisions.
  • Decide whether weekly automation and a presentation walkthrough are required.
  • Retain additive measurement revisions. Never invalidate Card 03 v1 or rewrite a historical security finding.
  • Keep new target builds revision-locked with patch-set, executable, image, and manifest digests.
